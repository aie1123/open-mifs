# 托盘提示自定义（需求计划）

> 目标：鼠标悬停托盘图标时显示的摘要（当前为 `OpenMIFS v0.4.4 · 均衡 · 风扇 2495/2566 RPM`）
> 允许用户选择显示哪些项目、按什么顺序、用什么写法。

---

## 1. 现状（代码事实，不是猜测）

| 事实 | 位置 / 说明 |
| :--- | :--- |
| 提示内容是**硬编码拼接**的 | `TrayContext.RefreshTray()`：`"OpenMIFS v" + 版本` → `" · 均衡"` → `" · 风扇 a/b RPM"` |
| 已有截断逻辑 | `if (tip.Length > 62) tip = tip.Substring(0, 62);` |
| **上限 63 字符、单行** | .NET Framework 的 `NotifyIcon.Text` 限制；Win32 托盘提示不支持换行 |
| 刷新频率 | 托盘 5 秒（`_trayTimer`）；主窗体数据 3 秒（`_timer`，构造时就 `Start()`） |
| `--tray` 模式下数据仍在采集 | `_timer` 在 `MainForm` 构造函数里启动，不依赖窗口可见 → 传感器照常刷新 |
| 传感器值目前**没有对外暴露** | 只写进了窗体的键值行；托盘拿不到 CPU/GPU 温度这类值 |
| 设置已有持久化机制 | `Settings.Get/Set`（`%LOCALAPPDATA%\OpenMIFS\settings.txt`，键值对），当前只有一个 `osd_hint` |
| 右键菜单里的状态行 | `_miStatus.Text = "当前：" + ModeMap.Label(...)`，**没有长度限制** |

---

## 2. 目标 / 非目标

**目标**
1. 用户能选显示哪些项目，改完立即生效（不必重启）。
2. 超长时按优先级自动丢弃尾部项目，永不抛出/显示被截断的半个数字。
3. 悬停提示保持"一眼能读完"；完整信息放到右键菜单里（无长度限制）。

**非目标**
- 不做多行悬停提示（Win32 不支持）。
- 不做气泡弹窗轮播（会打扰，且需要定时弹 BalloonTip）。
- 不改动现有传感器采集逻辑。

---

## 3. 需求项

### R1 可选项目（勾选式，推荐默认）
可勾选清单（括号内为占位符名）：

| 项目 | 占位符 | 示例 | 建议默认 |
| :--- | :--- | :--- | :---: |
| 版本 | `{ver}` | `OpenMIFS v0.4.4` | ✅ |
| 性能模式 | `{mode}` | `均衡` | ✅ |
| 风扇 1/2（3 若存在） | `{fan1}` `{fan2}` `{fan3}` | `2495/2566` | ✅（合成一项） |
| CPU 温度 | `{cpu_temp}` | `58 ℃` | ☐ |
| CPU 功耗 | `{cpu_power}` | `24.7 W` | ☐ |
| CPU 频率 | `{cpu_freq}` | `3.43 GHz` | ☐ |
| CPU 负载 | `{cpu_load}` | `18%` | ☐ |
| GPU 温度 | `{gpu_temp}` | `57 ℃` | ☐ |
| GPU 功耗 / 频率 | `{gpu_power}` `{gpu_freq}` | `25 W` / `800 MHz` | ☐ |
| 内存占用 | `{mem}` | `16.2/31.2 GB` | ☐ |
| 磁盘温度 | `{disk_temp}` | `35 ℃` | ☐ |
| 电池 | `{battery}` | `92%` | ☐ |
| OSD 服务状态 | `{osd}` | `OSD 正常` | ☐ |
| 供电类型 | `{ac}` | `Type-C` | ☐ |

### R2 顺序与分隔符
- 顺序可调（上移/下移），默认与上表一致。
- 分隔符可选：`·`（默认）/ `/` / ` | ` / 空格。
- 空值项目自动跳过（不要把 `未实现` 塞进提示里）。

### R3 写法：两档
- **简单档（默认）**：勾选 + 顺序 + 分隔符，不用学语法。
- **模板档（进阶）**：一个文本框，如 `{mode} {fan1}/{fan2} {cpu_temp} {battery}`。
  - 实时预览 + 未知占位符标红 + 一键恢复默认。
  - 模板档优先级高于勾选档；模板为空则回落到简单档。

### R4 长度与降级（关键）
- 硬上限 **63 字符**；界面实时显示当前字数（`42/63`）。
- 超出时**从优先级最低的项目开始整项丢弃**，而不是按字符截断。
  - 优先级：`{mode}` `{cpu_temp}` `{fan1}{fan2}` `{battery}` `{ver}` …（可配置）
  - 丢弃后若仍超长，继续丢弃，直到放得下。
- 绝不出现被截断的数字（`风扇 2495/25…` 这种）。

### R5 第二展示面：右键菜单
右键菜单顶部状态行显示**完整**摘要（多行、无 63 限制）：
```
OpenMIFS v0.4.4
均衡 · 风扇 2495/2566 RPM
CPU 58 ℃ / 24.7 W / 3.43 GHz
GPU 57 ℃ / 25 W    内存 16.2/31.2 GB
```
内容同样由 R1/R2 的配置决定。勾选区里加一个开关「右键菜单显示详细摘要」。

### R6 持久化与恢复
- `settings.txt` 新增键：`tray_items`（逗号分隔 + 顺序）、`tray_sep`、`tray_template`、`tray_menu_detail`。
- 「恢复默认」按钮；配置损坏时回落默认并记日志（不能因为配置坏了就不显示提示）。

### R7 生效与开销
- 改动后**立即生效**：更新 `_tray.Text` 一次，不必等 5 秒定时器。
- 开销约束：托盘刷新沿用现有 5 秒节奏；勾选的传感器值取自**最近一次快照**，不额外触发采集。

## 4. 技术方案（落地要点）

1. **暴露传感器快照**：`MainForm` 维护 `static SensorSnapshot Last`（`RefreshSensors` 完成时写入；
   CPU 温度/功耗/频率/GPU 温度… 各一个字段）。托盘只读快照，不自己采集。
2. **渲染器**：`TrayText.Build(snapshot, config)` → 返回 `List<string>`（项目片段），
   再 `TrayText.Join(parts, sep, 63)` 做优先级丢弃。纯函数，**可单测**（无 UI 依赖）。
3. **配置解析**：`TrayConfig.Load()/Save()`，基于现有 `Settings`；未知项忽略并记日志。
4. **UI**：主窗体左侧新增分组「托盘提示」：勾选列表（`CheckedListBox`）+ 上移/下移 + 分隔符下拉 +
   模板文本框 + 预览（灰底只读 Label，显示字数）。
5. **右键菜单**：`_miStatus` 从单行升级为多行（`ToolStripMenuItem` 支持 `\n` 显示为多行）。

## 6. 验收标准（可测）

1. 勾 `{cpu_temp}` + `{battery}` → 悬停提示出现 `58 ℃` 与 `92%`，格式与预览一致。
2. 勾满 10 项 → 提示仍 ≤63 字符，且**没有任何被截断的数字**（逐项检查）。
3. 改变顺序/分隔符 → 立即生效，无需重启。
4. 重启程序、`--tray` 启动 → 配置保留，提示照常显示（证明快照在无窗口时也在更新）。
5. 手工把 `settings.txt` 改坏（乱码/未知项）→ 程序仍启动，提示回落默认，日志有告警。
6. `未实现` 的项（如未勾选风扇且 MIFS 不可用）不出现在提示里。

## 7. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 用户勾太多 → 提示被丢弃得看不懂 | 预览区实时显示最终文本 + 字数；超出时给出"已省略 N 项"的提示（在设置界面里提示，不写进托盘） |
| 传感器在 `--tray` 下未刷新导致空白 | 验收标准 4 专门覆盖；快照带时间戳，超过 15 秒未更新则不显示该项 |
| 托盘图标频繁重画（v0.5.3） | 只在数值变化时重画，`Icon` 旧对象必须 `Dispose` |
| 63 字符上限随系统/DPI 变化 | 保守按 62 截断（现有代码即如此），并在预览区按 63 提示 |

# OpenMIFS 界面设计定调（frontend-design 第一遍：计划 → 复核）

> 用 `frontend-design` 技能跑的设计定调。**本文只做定调与问题清单，不改代码。**
> 定调一旦确认，后续所有界面改动照这套 token 来，不再随手写颜色/字号。

---

## 0. 先把 brief 立起来（技能要求：从主题出发）

| 问题 | 回答 |
| :--- | :--- |
| 这是什么产品 | 一台**具体笔记本**（机械革命无界 14 Pro / 同方 MIFS）的硬件控制台，取代厂商没出的控制中心 |
| 使用者是谁 | 这台机器的主人：懂硬件的折腾型用户，中文，会看温度/功耗/频率/风扇 RPM |
| 首要任务 | **① 一眼读出机器现在的热与功耗状态；② 有把握地切换性能模式与硬件开关** |
| 次要任务 | OSD 排障、开机自启、托盘/图标偏好 |
| 材料的"行话" | ℃ / W / GHz / RPM / MT/s / SMU / EC / ACPI-WMI / 提权 / 未实现 |
| 使用节奏 | 常驻托盘，**每次打开看 3~10 秒就关掉** → 扫读优先于"浏览" |

**主视觉判断**：这个产品没有"hero"，它的主角是**实时读数**。所以设计的第一原则不是美观，而是**扫读速度**。

## 1. Token 系统

### 1.1 颜色（4~6 个命名值 + 一套语义色）

| 名称 | 值 | 用途 |
| :--- | :--- | :--- |
| `Surface` | `#F5F4F1` | 窗口底（略带暖灰，非纯白，减轻长时间盯屏） |
| `Recessed` | `#FFFFFF` | **只读读数面板**底色（凹陷感：白底 + 1px 内阴影线） |
| `Hairline` | `#E2DFD8` | 分隔细线（取代 7 个同款 GroupBox 边框） |
| `Ink` | `#1B1B1E` | 数值与正文 |
| `Label` | `#6B6B73` | 标签与单位（**实测对比度**：白底 5.28:1 / 窗口底 4.84:1，均 ≥4.5 ✓） |
| `Muted` | `#A1A1AA` | **只用于禁用态/未实现值/装饰线**（白底 2.6:1，不承载必须读到的信息） |

**语义色只有一套，且与托盘图标同源**（这是本项目唯一"大胆"的地方 —— 状态色跨图标/面板/OSD 三处守恒）：

| 档 | 值 | 含义 |
| :--- | :--- | :--- |
| 凉 | `#267642` | 绿（白底 5.6:1 ✓） |
| 温 | `#8A6510`（文字）／`#9E7614`（图标填充） | 琥珀 —— 原值 `#9E7614` 在白底只有 4.15:1，**文字场景**必须加深到 `#8A6510`（5.32:1）；图形填充按 WCAG 非文字 3:1 达标 |
| 热 | `#B04A18` | 橙（白底 5.5:1 ✓） |
| 烫 | `#A82424` | 红（白底 7.1:1 ✓） |

> **硬规则**：语义色只用于"状态判定"（温度档位、降频、错误、禁用原因），**绝不用于装饰**；交互态（选中/按下）用 `Ink` 墨块，不引入品牌色。

### 1.2 字体（两个角色，各自有理由）

| 角色 | 字体 | 字号 | 颜色 | 理由 |
| :--- | :--- | :--- | :--- | :--- |
| **数值** | `Consolas` | 11pt Bold | 按档位 / `Ink` | **等宽**让 `10.6 W → 105.5 W` 不抖动、小数点对齐（这是功能需求，不是风格——技能把"等宽小标签"列为 AI 味，但此处是为**实时跳动的数字**选的） |
| 单位/后缀 | `Microsoft YaHei UI` | 8pt | `Muted` | 紧贴数值右侧 4px |
| 标签 | `Microsoft YaHei UI` | 8pt | `Label` | 右对齐到固定列宽 |
| 区块标题 | `Microsoft YaHei UI` | 9pt Semibold | `Ink` | 句子式（**不用全大写、不做字距拉伸、不加眉标**） |
| 正文/按钮 | `Microsoft YaHei UI` | 9pt | `Ink` | |

### 1.3 间距（4px 基）

`4 / 8 / 12 / 16 / 24 / 32`。
- 控件内边距 8；同组控件间距 8；**组间 24**（现在混着用）
- 读数行高 24（8pt 标签 + 11pt 数值的呼吸感）；控制行高 28
- 面板内边距 12

### 1.4 圆角与"表面语义"（本设计的关键决定）

| 表面 | 圆角 | 含义 |
| :--- | :--- | :--- |
| 只读读数面板 | **0**（方角）+ 1px 内线 | **凹陷 = 仪器表盘**：数据在你之外，你只能读 |
| 可交互控件（按钮/下拉/输入） | 4 | **平面/凸起 = 你可以动它** |

> 这一条替代了现在"7 个一模一样的 GroupBox"的做法：**表面形态本身编码"只读 vs 可操作"**，不需要靠标题文字去猜。

**对齐规则**
- 左列：全部控件左缘对齐同一条线（x=12）；标题与控件同左缘
- 右列：标签**右对齐**到 92px 列宽 → 数值**右对齐**到下一列（等宽字体保证小数点成列）→ 单位**左对齐**紧贴数值 4px
- 不使用居中（除窗口整体）

## 3. 设计原则（5 条，改任何界面都按这个判）

1. **数值是主角**：每个读数里数值字号最大、颜色最深；标签与单位退到 8pt 灰。现在值与标签同字号同重量，是本界面最贵的视觉债。
2. **凹陷=只读，平面=可操作**：表面形态编码交互性，不靠标题说明。
3. **一套语义色跨三处守恒**（托盘图标 / 面板 / OSD 提示）；数据永不使用装饰色。
4. **一处大胆，其余克制**：唯一的"重"元素是性能模式的实体拨杆式分段控件；别处一律安静（细线、留白）。
5. **文案即界面**：动作就是结果（"重启 OSD" → 完成后提示"OSD 已重启"）；失败说清原因与下一步；未实现项不占视觉权重。

## 4. 复核（技能要求的第二遍：对照 brief 挑"默认值味道"）

按技能列出的 AI 生成通病逐条自查，**3 处改了**：

| 通病 | 本方案 | 处理 |
| :--- | :--- | :--- |
| 暖奶油底 + 高对比衬线 + 陶土色 `#D97757` | 我有暖灰底 `#F5F4F1` | ⚠️ **改**：底色去暖，用中性 `#F5F5F4`；不使用任何陶土/暖橙作强调色（暖色只以"档位语义"出现） |
| 近黑底 + 单一酸绿/朱红 | 不用 | ✅ 规避 |
| 报纸式细线 + 零圆角 + 密排 | 我用细线 | ⚠️ **改**：细线只用于**分区**（3 处），不做密排；交互控件圆角 4，避免"全零圆角"的报纸感 |
| SaaS 卡片套装（同款圆角卡 + 同款阴影） | **现在正是这样**（7 个同款 GroupBox） | ✅ 已列为头号问题（见 §5‑H1） |
| `·` 连接的 meta 串 | 现在顶部状态条与传感器底栏都是 | ⚠️ **改**：顶部改为**徽标 + 计数**；`·` 仅保留在托盘 62 字符 ToolTip（那里是必要的紧凑分隔） |
| 全大写眉标 / `WORD — fragment` / 链接加 `→` | 中文界面，不用 | ✅ 规避 |
| 小数据用等宽字体 | 数值用 Consolas | ✅ 保留（理由：实时数值需对齐、防抖动，属"为 brief 做的选择"） |

**结论**：方案与"任何仪表盘都会产出的默认稿"已有可辨差异（表面语义 + 状态色跨端守恒 + 数值主角），可以进入实现。

## 6. 第一轮建议（改完视觉提升最大、风险最低）

| 顺序 | 改动 | 触及范围 | 估时 |
| :---: | :--- | :--- | :--- |
| 1 | **字阶与数值主角**（H2+H3）：值 11pt Consolas Bold 右对齐、标签/单位 8pt 灰 | `KvRow` 渲染 + `RenderKeyValues` | 40 分钟 |
| 2 | **表面语义**（H1）：读数区换凹陷方角面板；控制区去外框走细线 + 24 节奏 | `BuildUi` 左列 + 右列面板 | 1 小时 |
| 3 | **状态条重做**（C1+M2）：单行徽标+计数，去掉 `·` meta 串与红字两行 | `_lblHeader` + 传感器底栏 | 40 分钟 |
| 4 | **未实现折叠**（C2+C4）：状态面板与未实现分组折叠成一行「▸ N 项」 | 面板渲染 + 折叠控件 | 40 分钟 |
| 5 | **读数分簇**（C3）：传感器 16 行分三簇 + 簇间细线 + 关键指标置顶 | `SensorOrder` + 渲染 | 30 分钟 |

> 合计约 3.5 小时，建议按 1→5 顺序做，每步都能单独截图验收；其中第 1、3 步收益最直观。

## 7. 验收方式（沿用本项目纪律）

1. 每步改完用 asInvoker 副本截图（AGENTS.md §5 套路），与上一张并排对比
2. 数值列对齐检查：随机取 3 个不同位数的值（`9 %` / `14 %` / `105.5 W`），确认小数点在一条竖线上
3. 对比度（已实测，写进 token 表）：标签 `#6B6B73` 白底 **5.28:1** / 窗口底 **4.84:1**；
   语义四色文字版 5.60 / 5.32 / 5.47 / 7.14:1 全部 ≥4.5；`Muted #A1A1AA` 仅 2.56:1，**只准用于禁用/未实现/装饰**
4. 未实现项折叠后，首屏必须能一眼看到：性能模式、风扇转速、CPU 温度/功耗 —— 四项都在
